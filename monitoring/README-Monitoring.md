# Monitoring — Prometheus + Grafana

> Observability stack for HomeLab SIEM — infrastructure metrics via Prometheus,
> visualized in Grafana with custom SIEM dashboards.

---

## Architecture

```
[HomeLab SIEM]  →  /metrics endpoint (prometheus-client)
      ↓
[Prometheus]  →  scrape every 15s  →  time-series DB (7d retention)
      ↓
[Grafana]  →  query Prometheus  →  live dashboards
```

---

## Prerequisites

- k3d cluster with monitoring ports mapped (see §1)
- Helm installed (`sudo snap install helm --classic`)
- `prometheus-client>=0.20.0` in `requirements.txt`

---

## 1. Recreate Cluster with All Ports

The cluster must expose ports for Prometheus and Grafana at creation time.
If your current cluster does not have them, recreate it:

```bash
./monitoring/setup-monitoring.sh restart-cluster
```

This maps:

| Port | Service |
|---|---|
| 30500 | SIEM Dashboard |
| 30514 | Syslog UDP |
| 30090 | Prometheus |
| 30300 | Grafana |

> **Note:** Recreating the cluster deletes the SQLite PVC. Back up your data first.

---

## 2. Install Monitoring Stack

```bash
chmod +x monitoring/setup-monitoring.sh
./monitoring/setup-monitoring.sh install
```

The script installs in order:
1. Scales down SIEM (frees RAM during install)
2. Installs Prometheus and waits for stability
3. Installs Grafana and waits for stability
4. Restarts SIEM

Total time: ~5 minutes.

---

## 4. Configure Grafana

### Add Prometheus as data source

1. Grafana → Connections → Data sources → Add data source
2. Select **Prometheus**
3. URL: `http://prometheus-server.monitoring.svc.cluster.local`
4. Click **Save & test**

### Import SIEM dashboard

1. Grafana → Dashboards → Import
2. Upload `monitoring/grafana-dashboard.json`
3. Select Prometheus as data source
4. Click **Import**

---

## 5. SIEM Custom Metrics

The SIEM exposes custom metrics at `/metrics`:

| Metric | Type | Description |
|---|---|---|
| `siem_events_total` | Counter | Events ingested by category and source |
| `siem_alerts_total` | Counter | Alerts generated by rule_id and severity |
| `siem_active_alerts` | Gauge | Active alerts by severity |
| `siem_rules_loaded_total` | Gauge | Detection rules loaded |
| `siem_http_request_duration_seconds` | Histogram | API request latency |
| `siem_ingest_requests_total` | Counter | Ingest API requests by status |

### Enable in app.py

Add to `requirements.txt`:
```
prometheus-client>=0.20.0
```

Add to `app.py`:
```python
from monitoring.siem_metrics import setup_metrics, metrics_bp
setup_metrics(app)
app.register_blueprint(metrics_bp)
```

## 6. Commands

```bash
./monitoring/setup-monitoring.sh install          # Full install
./monitoring/setup-monitoring.sh status           # Show status and URLs
./monitoring/setup-monitoring.sh teardown         # Remove monitoring stack
./monitoring/setup-monitoring.sh restart-cluster  # Recreate cluster with all ports
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Pods in CrashLoopBackOff | Insufficient RAM during startup | Scale down SIEM first, then install |
| Grafana unreachable | Port not mapped in cluster | Run `restart-cluster` |
| No metrics in Grafana | `/metrics` endpoint missing | Add `siem_metrics.py` to app.py |
| Prometheus targets DOWN | Wrong scrape URL | Check `prometheus-scrape-config.yaml` |
